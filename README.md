# FTX-1 Region / EEPROM Tool

Инструмент для Yaesu **FTX-1**: чтение и запись служебной EEPROM через CAT,
дамп EEPROM и смена региона (destination code), включая «широкие» коды
MARS/CAP.

Один файл, без зависимостей кроме `pyserial`. Работает по обычному USB-кабелю,
вскрывать радио и цеплять CH341A не нужно.

---

## ⚠️ Прочитайте перед использованием

- Передавать можно **только** там, где это разрешено вашей лицензией.
- Смена региона может нарушать типовое одобрение (type approval) и условия
  гарантии.
- Запись идёт в служебную EEPROM. Перед первой записью **обязательно** сделайте
  дамп: `python ftx1_region.py dump`.
- Калибровочная таблица лежит рядом (`0x000A..0x0108`). Инструмент её не
  трогает, но команда `write` умеет писать любой байт — не используйте её
  вслепую.
- Автор не несёт ответственности за испорченное оборудование.

---

## Что умеет

| Команда | Назначение |
|---|---|
| *(без команды)* | интерактивное меню: info / dump / list / set / ports |
| `ports` | список COM-портов, помечает порт CAT |
| `info` | ID, версия прошивки, текущий регион, TX-диапазоны |
| `list` | таблица всех известных кодов регионов |
| `dump` | дамп EEPROM в `.bin` + `.txt` с SHA-256 |
| `set` | смена региона: показывает разницу, делает бэкап, спрашивает подтверждение |
| `read` | прочитать один байт EEPROM |
| `write` | записать один байт EEPROM (для продвинутых) |

## Требования

- Python 3.8 или новее
- `pyserial` — **ставится автоматически при первом запуске**, если его нет

Ручная установка (необязательно):

```bash
pip install -r requirements.txt
```

При первом запуске без `pyserial` скрипт сам вызывает `pip install` (при
необходимости с `--user`, а если pip недоступен — сначала `ensurepip`). Нужен
только интернет в этот первый раз. Отключить автоустановку:
`FTX1_NO_AUTOINSTALL=1` — тогда скрипт попросит поставить библиотеку вручную.

Windows, Linux и macOS. На Linux порт обычно `/dev/ttyUSB0`, на macOS —
`/dev/cu.SLAB_USBtoUART` или `/dev/cu.usbserial-*`.

## Быстрый старт

Самый простой путь — запустить без аргументов:

```bash
python ftx1_region.py
```

Откроется меню, где всё делается по цифрам. При первом запуске скрипт
спрашивает язык (русский / English / оба), выбор запоминается; пункт `6`
меняет язык в любой момент.

Русский:

```
FTX-1: регионы и EEPROM

  1  info    текущий регион, прошивка, диапазоны
  2  dump    дамп EEPROM (первые 4 КБ, ~50 с)
  3  list    таблица регионов
  4  set     выбрать и записать регион
  5  ports   список COM-портов
  6  lang    сменить язык / change language
  0  выход
```

English:

```
FTX-1: regions and EEPROM

  1  info    current region, firmware, TX ranges
  2  dump    back up EEPROM (first 4 KiB, ~50 s)
  3  list    all known region codes
  4  set     choose a region and write it
  5  ports   list serial ports
  6  lang    change language / сменить язык
  0  exit
```

Пункт `4` показывает таблицу регионов, спрашивает код, делает бэкап и требует
подтверждение `yes` перед записью. Ниже — то же самое отдельными командами.

### Язык интерфейса

- При первом запуске — выбор: `1` русский, `2` English, `3` оба (описания
  регионов тогда показываются как `EN \ RU`).
- Выбор сохраняется в `~/.ftx1_region_lang` и используется в следующих запусках.
- Сменить на лету: пункт `6` в меню.
- Разово, без сохранения: `python ftx1_region.py --lang en list`.
- `--lang` работает и до, и после команды: `... list --lang en`.
- Низкоуровневые ошибки SPR/SPW/ID остаются на английском — это диагностика
  протокола.

1. Включите радио, подключите USB. В диспетчере устройств должно быть **два**
   порта Silicon Labs CP2105: `Standard` и `Enhanced`. CAT — это **Enhanced**.
2. Найдите порт:

   ```bash
   python ftx1_region.py ports
   ```

   ```
   COM14  Silicon Labs Dual CP2105 ... Enhanced COM  10C4:EA70   <-- CAT port
   ```

3. Проверьте связь и текущий регион:

   ```bash
   python ftx1_region.py info
   ```

   ```
   порт      : COM14 @ 38400
   ID        : ID0840;
   прошивка  : VE00113;
   регион    : 0xB5A7  B2(EU)_MC
   байты     : B5 A7  флаг 00
   описание  : classic MARS/CAP: 1.8-30 MHz continuous \
               классический MARS/CAP: 1.8-30 МГц сплошняком

   Диапазоны передачи (5):
     ┌───────────────────────────┐
     │    1.8000 -   30.0000 МГц │
     │   50.0000 -   54.0000 МГц │
     │   70.0000 -   70.5000 МГц │
     │  144.0000 -  148.0000 МГц │
     │  430.0000 -  450.0000 МГц │
     └───────────────────────────┘
   ```

4. Сделайте дамп (по умолчанию первые 4 КБ — заголовок, калибровка, регион):

   ```bash
   python ftx1_region.py dump
   ```

5. Посмотрите доступные регионы:

   ```bash
   python ftx1_region.py list
   ```

6. Смените регион:

   ```bash
   python ftx1_region.py set B5A7
   ```

   Инструмент покажет, что было и что станет, сохранит бэкап в `backups/` и
   попросит ввести `yes`.

7. **Выключите и включите радио** (полный цикл питания), затем снова `info`.

## Команды подробно

### запуск без команды (меню)

```bash
python ftx1_region.py                 # автоопределение порта
python ftx1_region.py --port COM14    # указать порт для меню
```

Показывает меню с пунктами 1–5 и `0` для выхода. Работает в цикле: после
каждого действия возвращается в меню. Ошибки CAT не роняют программу, а
печатаются и меню продолжает работу. Запись региона по-прежнему требует
подтверждения `yes`, так что случайно ничего не изменится.

### `ports`

Показывает все COM-порты. Порт CAT помечается `<-- CAT port>`.

### `info [--port COMx] [--baud 38400]`

Читает `ID;`, `VE0;` и три байта региона. Показывает код, имя и полный список
TX-диапазонов, которые прошивка разрешает для этого кода.

### `list`

Таблица: код, имя, «широкий» ли, краткое описание.

### `dump [--start 0x0000] [--length 0x1000] [--full] [--out FILE] [--double]`

- по умолчанию: `0x0000..0x0FFF` (4 КБ, около 50 секунд);
- `--full`: все 64 КБ, доступные по 16-битному адресу (около 13 минут);
- `--double`: прочитать дважды и сравнить;
- рядом с `.bin` пишется `.txt`: дата, порт, ID, прошивка, регион, SHA-256,
  число сбойных байт.

Куда сохраняется:

- без `--out` — в папку **`dumps/` рядом со скриптом**, имя
  `eeprom_<start>_<end>_<дата>_<время>.bin`;
- с `--out FILE` — ровно туда, куда указали (относительный путь считается от
  текущего каталога).

В конце печатается полный путь к файлу.

Скорость около 12 мс на байт (протокол читает по одному байту).

### `set [CODE] [--dry-run] [--yes] [--force] [--no-backup]`

`CODE` — hex (`B5A7`, `0xB5A7`) или имя региона (`"B2(EU)_MC"`).
Если `CODE` не указан, инструмент покажет таблицу и спросит код вручную.

Что делает:

1. читает текущий код;
2. если код неизвестен — отказывается писать (обойти: `--force`);
3. показывает старый и новый регион и их TX-диапазоны;
4. `--dry-run` — на этом останавливается, ничего не записывая;
5. сохраняет `backups/eeprom_head_<дата>.bin` (0x0000..0x01FF) и проверяет его:
   если хоть один байт не прочитался или регион в бэкапе не совпал с текущим,
   запись отменяется;
6. спрашивает `yes` (обойти: `--yes`);
7. пишет два байта в `0x0109`/`0x010A`;
8. проверяет чтением. Сразу после смены кода прошивка переключает таблицы
   диапазонов, поэтому первые чтения могут не пройти — инструмент делает
   несколько попыток с паузами. Если всё равно не прочиталось, он пишет
   `write sent, but the readback failed` и просит перезагрузить радио: это не
   ошибка записи, проверьте `info` после выключения/включения.

Посмотреть, что будет, ничего не меняя:

```bash
python ftx1_region.py set --dry-run 0x1CB9
```

### `read ADDR` / `write ADDR VALUE`

Одиночный байт. `write` спрашивает подтверждение и проверяет результат.
Пример: `python ftx1_region.py write 0x0109 0xB5`.

## Регионы

Коды и TX-таблицы извлечены из MAIN V01.13 (см. «Как это работает»).

Описания зависят от выбранного языка: `ru` — только русский, `en` — только
английский, `both` — оба через обратный слэш (**English \ Русский**). Так их
показывают `list`, `info` и `set`. В таблице ниже приведён режим `both`.

| Код | Имя | Широкий | Описание (EN \ RU) |
|---|---|---|---|
| `0x7753` | AUS | – | Australian band plan, 12 narrow rows \ австралийский план, 12 узких участков |
| `0x1CB9` | DEV | да | widest: 30 kHz - 75 MHz continuous \ самый широкий: 30 кГц - 75 МГц сплошняком |
| `0xB5A7` | B2(EU)\_MC | да | classic MARS/CAP: 1.8-30 MHz continuous \ классический MARS/CAP: 1.8-30 МГц сплошняком |
| `0x50E2` | USA\_MC | да | same TX table as B2(EU)\_MC \ та же TX-таблица, что у B2(EU)\_MC |
| `0xA4C5` | C2(UK)\_MC | да | same TX table as B2(EU)\_MC \ та же TX-таблица, что у B2(EU)\_MC |
| `0x315B` | USA | – | 23 rows: ham bands + 5 MHz channels \ 23 участка: любительские диапазоны + каналы 5 МГц |
| `0xA983` | B2(EU) | – | 13 rows, includes 5351.5 kHz \ 13 участков, включая 5351.5 кГц |
| `0xD950` | C2(UK) | – | 14 rows, includes 5250 kHz \ 14 участков, включая 5250 кГц |
| `0xD32D` | CHINA | – | 12 rows \ 12 участков |
| `0x6DA0` | EXP(B3) | – | 12 rows \ 12 участков |
| `0x4380` | blank/default | – | 19 sub-band rows (not continuous) \ 19 поддиапазонов (не сплошняком) |
| `0x25BA` | JPN | – | no TX table in the dispatcher (firmware default path) \ отдельной TX-таблицы нет (ветка прошивки по умолчанию) |

Так это выглядит на экране (`python ftx1_region.py list`):

```
Регионы FTX-1 (MAIN V01.13)

  ┌────────┬───────────────┬─────────┬────────────────────────────────────────────────────────────────┐
  │ код    │ имя           │ широкий │ описание (EN \ RU)                                             │
  ├────────┼───────────────┼─────────┼────────────────────────────────────────────────────────────────┤
  │ 0x1CB9 │ DEV           │ да      │ widest: 30 kHz - 75 MHz continuous \ самый широкий: 30 кГц -   │
  │        │               │         │ 75 МГц сплошняком                                              │
  ├────────┼───────────────┼─────────┼────────────────────────────────────────────────────────────────┤
  │ 0x50E2 │ USA_MC        │ да      │ same TX table as B2(EU)_MC \ та же TX-таблица, что у B2(EU)_MC │
  ├────────┼───────────────┼─────────┼────────────────────────────────────────────────────────────────┤
  │ 0xB5A7 │ B2(EU)_MC     │ да      │ classic MARS/CAP: 1.8-30 MHz continuous \ классический         │
  │        │               │         │ MARS/CAP: 1.8-30 МГц сплошняком                                │
  └────────┴───────────────┴─────────┴────────────────────────────────────────────────────────────────┘
```

Рамки рисуются символом `─│┌┐└┘├┤┬┴┼`. Если консоль их не умеет (например,
cp1251 при перенаправлении вывода), инструмент сам переходит на `+-|`, так что
вывод не ломается.

Практический выбор:

- **`0xB5A7`** — классический MARS/CAP: сплошные 1.8–30 МГц (включая 60 м и
  27 МГц), плюс 6 м, 4 м, 2 м, 70 см. Рекомендуется.
- **`0x1CB9`** — максимально широко (30 кГц–75 МГц). Учтите, что тракт и
  фильтры рассчитаны на КВ/6 м/2 м/70 см, поэтому участки 30–50 и 54–70 МГц
  могут быть бесполезны или давать побочные излучения.
- **`0x50E2` / `0xA4C5`** — та же TX-таблица, что у `0xB5A7`, отличаются
  раскладкой меню/памяти.

## Куда именно пишется

```
EEPROM 0x0109 : B5   <- старший байт кода (big-endian)
EEPROM 0x010A : A7   <- младший байт
EEPROM 0x010B : 00   <- флаг, инструмент его НЕ трогает
```

У FT-710 код лежит по `0x010F`; у FTX-1 — по `0x0109`. Адрес проверен на живом
радио: до записи там было `77 53` (`0x7753`, AUS), после — `B5 A7`.

Автобэкап перед записью: `0x0000..0x01FF` (заголовок, калибровка, регион).

## Откат

Вернуть исходный регион:

```bash
python ftx1_region.py set 0x7753
```

Или вручную, двумя кадрами `SPW` (если пишете своей программой):

```
SPW 01 09 77 7B 3B      # 0x0109 = 0x77
SPW 01 0A 53 58 3B      # 0x010A = 0x53
```

Полный откат из дампа: `python ftx1_region.py write 0x0109 <байт>` для каждого
байта (медленно, но надёжно).

## Как это работает

### Протокол

FTX-1 (как и FT-710) поддерживает недокументированные сервисные команды
`SPR`/`SPW` — чтение и запись одного байта EEPROM.

```
SPR <aH> <aL> <sum> ;          ->  SPR <aH> <aL> <data> <sum> ;
SPW <aH> <aL> <data> <sum> ;   ->  (пусто) или ?;
```

- адрес 16-битный, big-endian;
- `sum` — 8-битная сумма всех байт кадра от `S` до байта перед `sum`
  включительно, по модулю 256;
- ответ `SPR` — ровно 8 байт, сумма считается по первым шести;
- около 5–12 мс на байт.

**Важная тонкость:** ответ `SPR` надо читать строго 8 байт. Байт данных и
контрольная сумма могут быть равны `0x3B` (`;`), и если обрывать чтение по
первому `;`, поток разъезжается на байт: все следующие ответы приходят от
предыдущих адресов, а проверка суммы при этом проходит. Именно из-за этого
в первой версии скрипта дампы получались битыми. В коде это `_txn_exact()`.

Пример: `SPR 01 09` → сумма `53+50+52+01+09 = 0xFB`, кадр
`53 50 52 01 09 FB 3B`.

### Почему не `JP`

В FT-710 регион меняется командой `JP0710...;`. В FTX-1 команда `JP` в
таблице команд есть, но обработчик — заглушка: на `JP0710;` радио отвечает
`?;`. Поэтому инструмент использует `SPR`/`SPW` напрямую.

Проверено на живом радио:

```
ID;      -> ID0840;
JP0710;  -> ?;
SPIR;    -> 53 50 49 52 ... ;     (сервисные команды живы)
SPR 01 09-> 53 50 52 01 09 77 FB 3B
```

### Откуда взяты коды

Из образа MAIN V01.13:

- таблица команд CAT: `0xFFE80288` (отсортированный список `AB..ZI`), сразу за
  ней блок скрытых команд `DP SP EO FD KT PE ZZ VE JP A0 A1 A2 RL EX SW`;
- таблица регион→код: `0xFFE9CC5C`, записи `{u16 code; char name[4]}`;
- диспетчер TX: `tx_freq_allowed`, цепочка сравнений `0xFFEC7FBB`
  (`CMP #code, R1` + `BEQ` на стаб `0xFFEC800C + 13*k`);
- TX-таблицы: `0xFFE96474 .. 0xFFE967C4`, пары `(lo, hi)` в герцах.

Коды FTX-1 совпадают по значению с FT-710, но это факт из прошивки FTX-1, а не
перенос: число строк в каждой таблице тоже совпало при сверке.

## Ограничения

- `SPR`/`SPW` используют 16-битный адрес, поэтому доступны только первые
  64 КБ EEPROM (микросхема — 128 КБ). Регион, калибровка и настройки лежат в
  начале, так что этого достаточно.
- Полный дамп 64 КБ идёт около 13 минут.
- Флаг `0x010B` не изменяется: его назначение неизвестно, менять его не нужно.
- Инструмент рассчитан на FTX-1 с MAIN V01.13. На другой версии прошивки
  сначала сделайте дамп и проверьте `info`: адрес и коды могут отличаться.

## Если что-то не так

| Симптом | Что проверить |
|---|---|
| `unexpected reply to ID;` | радио включено? выбран порт **Enhanced**, а не Standard? скорость 38400? |
| `?;` на всё | не тот порт или не та скорость; попробуйте `--baud 9600`, `19200`, `38400`, `115200` |
| `SPR ... failed` | помехи/длинный кабель; инструмент делает 5 попыток с паузами, повторите команду |
| `SPR ... failed` после `set` | в первой версии — баг чтения байта `0x3B`, запись при этом уже прошла; проверьте `info`. В исправленной версии не воспроизводится |
| `write sent, but the readback failed` | запись ушла, а чтение попало в момент перезагрузки таблиц; выключите/включите радио и проверьте `info` |
| В дампе `bad` больше нуля | плохой контакт/кабель или помехи. Исправленная версия читает строго 8 байт и даёт `bad 0`; повторите дамп |
| Файлы `*_CORRUPT.bin` | сделаны первой версией скрипта с багом чтения `0x3B`; для восстановления не годятся, оставлены только как история |
| Регион вернулся после перезагрузки | прошивка восстанавливает код при старте; тогда нужен CH341A и правка дампа |
| Дамп идёт очень медленно | это нормально: около 12 мс на байт |
| `ports` показывает кракозябры в названиях Bluetooth-портов | это системные описания, на работу не влияет |
| Не могу найти дамп или бэкап | `dumps/` и `backups/` лежат рядом со скриптом `ftx1_region.py`; полный путь печатается после сохранения |
| Вместо русского — `????` или кракозябры | консоль не в той кодировке: в Windows выполните `chcp 65001` или запустите в Windows Terminal. Рамки при этом автоматически заменяются на `+-|` |

независимо от того, из какого каталога вы запускали `python`.

## История исправлений

**09.11.2026 — чтение SPR**

Ответ `SPR` читался «до первого `0x3B`». Байт `0x3B` (`;`) может быть данными
или контрольной суммой, поэтому на первом же таком байте поток сдвигался, и
все следующие ответы приходили от предыдущих адресов — с правильной суммой,
поэтому проверка их не отбраковывала. Следствия:

- дампы и автобэкапы получались битыми (`bad` в сотнях байт);
- `set` мог написать регион, а потом упасть с `SPR ... failed` на проверке.

Исправлено: ответ читается ровно 8 байт (`_txn_exact`), при сбое буфер
очищается и попытка повторяется, бэкап перед записью проверяется (битый —
запись отменяется), `ID;` тоже проверяется. Дампы, сделанные до этого,
помечены `_CORRUPT`.
